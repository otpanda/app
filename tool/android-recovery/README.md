# Inactive Android enrolled-device primitive

Android11+ platform BiometricPrompt/AndroidKeyStore draft, not registered with any Activity, method channel or Flutter host. No network enrollment, session issuance, recovery effect or reset is implemented. Production auth/bootstrap gates unchanged. Stable package and signing identity remain a release condition, not a preview enrollment target.

A P-256 signing key has per-use strong biometric OR device credential authentication, including OS PIN/password/pattern fallback, and no inactivity expiry. Combined-auth biometric-enrollment exception is explicit in the official Builder setUserAuthenticationRequired documentation: https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder . Explicit setInvalidatedByBiometricEnrollment(false) records that policy. Removing/resetting the screen lock can still invalidate it. No hardware or attestation assurance is claimed.

Creation requires access to noBackup metadata first. A confirmed record without its key or with mismatching public key fails closed before key creation. Interrupted enrollment can reuse an existing alias only after KeyInfo confirms required authentication, per-use duration (-1) and exactly strong-biometric OR device-credential policy. Official KeyInfo duration documentation: https://developer.android.com/reference/android/security/keystore/KeyInfo . It never replaces or deletes a key. Server must reconcile possession under separate fresh enrollment authority, preserving revoked-key tombstones. Metadata is atomic, bounded and idempotently saved only for an identical separately confirmed record. Process-wide locks prevent cross-instance create/save/prompt races. Cross-process hosts are unsupported.

Signing validates exact server domain-separated8field challenge bytes. Client clock upper bound was removed for lagging-clock tolerance; expiry is rechecked after prompt, server remains authoritative. Ahead clocks fail closed and need host clock guidance. Step-up signing deliberately rejects until a digest-bound human-readable action display is designed. Enrollment/recovery prompts name their distinct purposes, do not present opaque ownerID as identity or promise an account effect.

OS-returned Signature must be the submitted operation. Cancellation synchronously completes failure/clears pending even without framework callback. Owning Activity stop/destroy cancels, pause alone does not; generations suppress late data and discarded signatures are zeroed. Real OS credential UI, multiwindow, cancellation races, process death, alias policy, direct-sign denial, backup/cloud/D2D and lock changes still need device tests. Compilation is not lifecycle proof.

Run check.sh with KOTLIN_LIB and ANDROID_JAR. It executes JVM exact byte/schema/skew tests,128 real ECDSA signatures, deterministic33byte padded/31byte short/nonminimal DER cases, metadata tests, shared fixed public SPKI/message/signature vector and native Android API compile. The fixed fixture contains no private key. Independent reviewer has executed Node side, not Kotlin yet. No publication or activation clearance is implied.

# Unwired server-anchored generated-code contract

The contract is still not imported by the app, browser bridge, native adapter or extension. No UI, display/copy, background polling, storage, seed import or live route is added. API67's unmounted response is extended with millisecond serverNow sampled by the same trusted server clock as its final validity check. Code intervals remain Unix seconds; session expiry remains milliseconds.

A caller supplies one continuing monotonic-millisecond clock (for example a started Stopwatch), not DateTime.now or a clock restarted for each request. load records its tick before both session and code requests. After decoding the response, it subtracts the entire elapsed load time from both the code's server-window remainder and the session's server-anchored remainder. The earlier expiry becomes an in-memory monotonic deadline. Subtracting the whole round trip, including time before serverNow was sampled, deliberately expires early rather than extending a code. Local wall-clock settings and wall-clock changes do not affect this calculation. A response already expired under that conservative bound is rejected, without automatic retry.

visible and remainingSeconds read the injected monotonic clock directly. Invalid/negative/unsafe or observed backward ticks clear state. Once expiry is observed the code is discarded. The timestamp, duration and deadline arithmetic is bounded to safe integers on JavaScript too. The contract requires exactly the code fields plus serverNow; old five-field responses fail closed. API and client changes remain separately unmounted/unwired, so there is no live mixed-version migration.

This is time anchoring, not guaranteed synchronized time. The server clock must be correct and sufficiently stable across the requests. The supplied monotonic clock must continue advancing over the lifetime of the view. Platform clocks can pause across sleep or suspension, so a future integration MUST clear on backgrounding, suspension/resume, logout, account switch and permission/catalog changes before display/copy, and acquire fresh server state on return. It must not retain the code object or use load completion as a success/copy signal; superseded loads complete without success. Check visible immediately before display/copy. No lifecycle wiring or revocation notifications are supplied here, and no platform sleep behavior is claimed tested. These remain prerequisites before real display/copy integration.

The store retains one selected entry, memory only. clear drops references without guaranteed string erasure. Errors and string representations are redacted. JSON integral syntax can decode differently on VM and web, so tests reject actual fractional values. Encoded identifiers beyond the server query cap fail generically. Synthetic tests cover server anchoring, full-delay subtraction, session clamp, exact deadline, rollback, malformed data, stale success/failure and clear during either await. Production authentication, key custody, enrollment and activation remain separate unfinished work. Durable-device work is unchanged.

Freshness is a transport requirement, not something serverNow proves on its own. The transport MUST obtain a fresh authenticated HTTPS response for each request, honor no-store, never memoize/replay cached bodies, never use stale fallback or a service-worker cached response, and never silently retry by returning an earlier response. Integration must verify this with an actual browser/native adapter, including service-worker behavior, before display/copy. A replayed old body could otherwise be treated as current. The server's timestamp is trusted only under that requirement. No local-wall-clock sanity bound is used. A coarse bound of minutes would allow skew below its chosen limit and reject older replays, but would also fail on clocks beyond that limit. This contract deliberately has no such limit, so an arbitrarily old replay would be accepted if the required freshness precondition fails. A nonce-bound protocol could reject ordinary stale-cache responses, but would not protect against an adapter that rewrites responses and adds protocol and transport surface here; it is deferred, not claimed implemented. This isolated contract is not sufficient for live integration until transport freshness is verified.

Provider recovery: clear deliberately retains the observed monotonic high-water mark. A backward/restarted provider remains fail-closed until it catches up; callers must instead discard this store and construct a new one with a continuing monotonic provider and fresh network state. Do not restart the provider on an existing store. An invalid visibility tick also cancels in-flight loads. Tests discriminate negative/backward initial ticks, in-flight rollback and slow-session/fast-code elapsed accounting. No real platform recovery or sleep behavior is implied.

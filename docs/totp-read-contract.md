# Unwired generated-code client contract

`TotpReadStore` is not imported by the app, browser bridge, native adapter or extension. It does not enable TOTP in any deployed client. It accepts the existing session-only transport and reads one selected entry, using the unmounted API67 contract. No seed input/export, background polling, storage, clipboard or code display is added here.

Generated-code intervals are explicitly Unix seconds. Session expiry and the caller's current clock are milliseconds, matching the existing client. A code is visible only inside its exact validity interval and the checked session expiry. The contract validates field allowlist, bounded identifiers, six/eight digits, safe integer timestamps, period and epoch alignment. Output/error string representations are redacted. Malformed, stale, mismatched or failed responses clear the old code without retry.

The store is one selected-entry in-memory view, not a cache. A new load clears the previous view. Generation markers discard completions after clear or another selection, including older failures. A future integration must call clear on logout, account switch, backgrounding and permission/catalog changes. It must check visible with a live clock before rendering or copying and supply the existing session lifecycle. This contract alone does not prove revocation delivery or correct client clock synchronization; no new server-time synchronization policy is invented. Local clock skew can hide a valid response or accept a still-in-window stale local view until its local expiry. Activation needs review of those integration boundaries.

Synthetic tests cover seconds versus milliseconds, leading zeros, exact rollover, session expiry, malformed/extra fields, encoded selected-entry query, pending clear, replacement ordering and generic failures. They are not real-account, UI or platform integration proof. Production authentication/key custody, seed enrollment and later web-route exposure remain separate unfinished work. Durable-device work is unchanged.

A superseded load completes normally without asserting success. Callers must read visible with the current clock; completion alone must never cause a success indicator or a copy. clear drops references and does not guarantee string erasure. Integral JSON-number syntax is not distinguished on JavaScript targets: 30 and 30.0 can both decode as int on web, while fractional values such as30.5 are rejected on every target. The server emits integral period values. A long non-ASCII identifier can pass the local identifier check yet exceed the server encoded-query cap, yielding a generic failure. Clock skew must be solved and reviewed before UI/display wiring; no synchronized-validity claim is made.

# Realtime client (inactive until activation)

`tool/realtime-client.js` is a classic script loaded before `session-bootstrap.js` (brand_hosts.py copies it and adds the script tag). Without it, or without `WebSocket`, `OTPandaSession.realtimeState()` is `unsupported` and nothing connects. The stream is a content-free hint; every change is re-read through the normal authorized reads.

Server contract (api main 2966793, `src/realtime-http.js`, `src/realtime-hub.js`): `POST /auth/realtime/ticket` (bearer only, empty body) returns a 30 s single-use ticket; `GET /auth/realtime` upgrades with subprotocols `["otpanda.v1", ticket]`; the only message is `{"v":1,"t":"changed"}`; closes 4401 revoked, 4408 expired, 4429 replaced, 1008 unexpected.

Bridge: `OTPandaSession.realtimeSubscribe(listener)` returns an unsubscribe function. The first subscriber starts the single socket, the last one stops it. `listener(reason)` runs with `connect` (snapshot after every open) or `changed`. `realtimeState()` reports `stopped|connecting|open|backoff|paused|degraded|inactive|unsupported`. `clear()` and logout stop the socket and drop late results.

Behavior (engineering defaults, all in `DEFAULTS`, overridable only by tests): one socket per tab; hidden for 60 s closes it and visible reconnects with a snapshot; offline closes, online reconnects; refresh requests coalesce to one in flight plus one trailing with 1 s spacing; ticket 401 runs one normal session read (the same 401 handling as any read), a second 401 stops; 429/503 wait `Retry-After` (30 s default for 429) plus up to 1 s jitter, otherwise full-jitter exponential backoff capped at 60 s, reset after 30 s open; 404 means inactive, stop; 400/403/405 stop; 4401 runs the session check then backs off; 4408 or 1006 renews through `maintainSession` and reconnects within 1 s; 4429 waits 60 s and three in 10 min degrade to the existing refresh cadence for 5 min; three pre-open failures do the same.
